# 最小化与零 Credits 估算兜底设计

## 目标

1. 主窗口增加标准最小化按钮，点击后缩到任务栏。
2. 现有关闭按钮行为不变：点击“X”隐藏到系统托盘。
3. 当服务器 Analytics 返回有效日期行、但本周期 Credits 合计为零时，不再把它当作可用于额度估算的数据，改用现有本机用量估算流程。
4. 每张账号卡直接显示额度估算结果或简短的采集状态，不必展开“详情”才能看到。

## 根因

当前五个账号均已保存三次刷新观测，但 Analytics 观测的 Credits 上下限均为零。现有逻辑仍把这类响应标记为 Analytics 来源，并跳过本机兜底，因此无法生成估算上下限，界面只能显示“暂不可用”。

## 行为

### 主窗口按钮

- 在关闭按钮左侧增加最小化按钮。
- 点击最小化按钮设置窗口为标准最小化状态，任务栏保留应用入口。
- 点击关闭按钮、标题栏“X”或托盘相关关闭路径保持原有行为。

### 额度估算

- Analytics 响应结构有效且 Credits 上限大于零：继续优先使用服务器 Analytics。
- Analytics 响应结构有效但 Credits 上限等于零：视为“无可用 Credits”，进入现有本机用量兜底。
- 本机数据满足账号归属、周期边界和价格换算条件时，生成现有美元区间。
- 历史数据不足时不构造虚假数值，显示“额度估算：采集中，还需使用后刷新”。
- 已有估算时，卡片显示“单次周额度估算：US$X–Y”或“单次月额度估算：US$X–Y”。

## 兼容性

- 不修改 `auth.json`、账号快照和切换流程。
- 不改变额度百分比、周期类型、重置时间或缓存格式。
- 旧缓存仍可读取；下一次手动刷新会使用修正后的兜底选择。

## 验证

- Analytics 非空但 Credits 全为零时，单元测试证明调用本机兜底并记录 Local 来源。
- Analytics Credits 大于零时仍优先使用服务器结果。
- 主窗口 XAML/运行时测试证明最小化按钮存在且设置 `WindowState.Minimized`。
- 卡片测试覆盖有估算值和数据不足两种文本。
- 完整 Release 测试通过后发布并覆盖本机安装版本。
